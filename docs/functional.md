# Quizer — Документация проекта

> **Quizer** — веб-приложение для создания, редактирования и прохождения квизов (тестов) с системой аутентификации, авторизацией, подсчётом результатов и таблицей лидеров.

Данная документация описывает функциональные возможности, архитектуру и API проекта. Она предназначена для разработчиков и команды проекта.

## Обзор проекта

Quizer — это монолитное веб-приложение, состоящее из двух частей:

- **Бэкенд** — REST API на платформе **.NET 10** (ASP.NET Core Web API), реализующий бизнес-логику, аутентификацию и работу с базой данных.
- **Фронтенд** — одностраничное приложение (SPA) на **React 19** + **TypeScript** + **Vite**, предоставляющее пользовательский интерфейс.

Приложение позволяет:

- Регистрироваться и авторизовываться (JWT-аутентификация).
- Создавать, редактировать, публиковать и удалять квизы.
- Управлять вопросами и вариантами ответов внутри квиза.
- Проходить опубликованные квизы с автоматической проверкой ответов.
- Просматривать результаты прохождения и таблицу лидеров.

## Функциональные возможности

### 1. Аутентификация и авторизация

- **Регистрация** — создание нового пользователя (имя, email, пароль).
- **Авторизация** — вход по email и паролю с получением JWT-токена.
- **Авторизация по ролям/владельцу** — доступ к операциям над квизом ограничен его владельцем.
- Все эндпоинты, кроме регистрации и авторизации, требуют JWT-токен.

### 2. Управление квизами

- **Создание квиза** — создание черновика (Draft) с названием и описанием.
- **Редактирование** — изменение названия и описания (только в статусе Draft).
- **Публикация** — перевод квиза в статус Published (доступен для прохождения).
- **Удаление** — удаление квиза (только владельцем).
- **Просмотр списка** — пагинированный список квизов.
- **Просмотр деталей** — получение квиза с вопросами и ответами.

### 3. Управление вопросами

- **Добавление вопроса** — текст, тип (Open / SingleChoice / MultipleChoice), порядок, баллы.
- **Редактирование вопроса** — изменение всех полей.
- **Удаление вопроса** — удаление из квиза.
- **Просмотр списка вопросов** — пагинированный список.
- **Просмотр вопроса** — получение вопроса с вариантами ответов.

### 4. Управление ответами (вариантами)

- **Добавление ответа** — текст и флаг правильности.
- **Редактирование ответа** — изменение текста и флага правильности.
- **Удаление ответа** — удаление варианта.

### 5. Прохождение квиза (Attempt)

- **Создание попытки** — начало прохождения опубликованного квиза (одна попытка на пользователя на квиз).
- **Ответ на вопрос** — сохранение ответа пользователя (текст для Open, набор ID для выбора).
- **Завершение попытки** — завершение прохождения.
- **Автозавершение** — попытка автоматически завершается, когда отвечены все вопросы.
- **Просмотр попытки** — получение текущего состояния попытки.
- **Просмотр списка попыток** — пагинированный список попыток по квизу.

### 6. Результаты и лидеры

- **Результат попытки** — подсчёт баллов, правильных/неправильных ответов, детализация по каждому вопросу.
- **Таблица лидеров** — рейтинг пользователей по сумме баллов за завершённые попытки.

### 7. Типы вопросов и правила проверки

| Тип | Правило проверки |
|-----|------------------|
| **Open** (открытый) | Текстовый ответ сравнивается с правильным без учёта регистра. |
| **SingleChoice** (одиночный выбор) | Выбран ровно один правильный вариант. |
| **MultipleChoice** (множественный выбор) | Выбранное множество точно совпадает с множеством правильных вариантов. |

## Сценарии использования

### Сценарий 1: Регистрация пользователя

**Предварительные требования:** отсутствуют (эндпоинт публичный).

**Основной поток:**
1. Пользователь отправляет `POST /api/v1/users/register` с `name`, `email`, `password`.
2. Система проверяет валидность данных (email, пароль, имя).
3. Система проверяет уникальность email.
4. Создаётся пользователь, пароль хэшируется.
5. Возвращается `200 OK` с идентификатором созданного пользователя.

**Альтернативные потоки:**
- **2.1. Некорректные данные.** Если email имеет неверный формат, пароль короче 6 символов или имя пустое, система возвращает `400 Bad Request`.
- **3.1. Email уже занят.** Если пользователь с указанным email уже существует, система возвращает `409 Conflict`.

---

### Сценарий 2: Авторизация

**Предварительные требования:** пользователь зарегистрирован.

**Основной поток:**
1. Пользователь отправляет `POST /api/v1/users/authorize` с `email` и `password`.
2. Система проверяет валидность данных.
3. Система проверяет учётные данные.
4. Генерируется JWT-токен.
5. Возвращается `200 OK` с токеном.

**Альтернативные потоки:**
- **2.1. Некорректные данные.** Если email имеет неверный формат или пароль пустой, система возвращает `400 Bad Request`.
- **3.1. Неверные учётные данные.** Если email или пароль неверны, система возвращает `401 Unauthorized`.

---

### Сценарий 3: Создание квиза

**Предварительные требования:** пользователь авторизован (JWT-токен).

**Основной поток:**
1. Пользователь отправляет `POST /api/v1/quizzes` с `title` и `description`.
2. Система проверяет валидность данных.
3. Создаётся квиз в статусе `Draft`, владелец — текущий пользователь.
4. Возвращается `201 Created` с идентификатором созданного квиза.

**Альтернативные потоки:**
- **1.1. Не авторизован.** Если JWT-токен отсутствует или недействителен, система возвращает `401 Unauthorized`.
- **2.1. Некорректные данные.** Если название пустое или превышает 200 символов, либо описание превышает 2000 символов, система возвращает `400 Bad Request`.

- **1.1. Не авторизован.** Если JWT-токен отсутствует или недействителен, система возвращает `401 Unauthorized`.
- **2.1. Не владелец.** Если текущий пользователь не является владельцем квиза, система возвращает `403 Forbidden`.
- **2.2. Ответ, вопрос или квиз не найден.** Если квиз, вопрос или ответ с указанными идентификаторами не существует, система возвращает `404 Not Found`.
- **2.3. Квиз опубликован.** Если квиз находится в статусе `Published`, система возвращает `409 Conflict`.

### Сценарий 17: Создание попытки (начало прохождения)

**Предварительные требования:** пользователь авторизован; квиз опубликован.

**Основной поток:**
1. Пользователь отправляет `POST /api/v1/quizzes/{quizId}/attempts`.
2. Система проверяет, что квиз опубликован.
3. Система проверяет, что пользователь ещё не проходил этот квиз.
4. Создаётся попытка в статусе `InProgress`.
5. Возвращается `201 Created` с данными попытки.

**Альтернативные потоки:**
- **1.1. Не авторизован.** Если JWT-токен отсутствует или недействителен, система возвращает `401 Unauthorized`.
- **2.1. Квиз не найден.** Если квиз с указанным идентификатором не существует, система возвращает `404 Not Found`.
- **2.2. Квиз не опубликован.** Если квиз находится в статусе `Draft`, система возвращает `409 Conflict`.
- **3.1. Пользователь уже проходил этот квиз.** Если у пользователя уже есть попытка по этому квизу, система возвращает `409 Conflict`.

### Сценарий 20: Ответ на вопрос

**Предварительные требования:** пользователь авторизован и является владельцем попытки; попытка в статусе `InProgress`.

**Основной поток:**
1. Пользователь отправляет `POST /api/v1/quizzes/{quizId}/attempts/{attemptId}/questions/{questionId}/answer` с `textAnswer` или `selectedAnswerIds`.
2. Система проверяет валидность данных.
3. Система проверяет, что пользователь является владельцем попытки.
4. Ответ сохраняется и проверяется.
5. Если отвечены все вопросы, попытка автоматически завершается.
6. Возвращается `200 OK` с результатом проверки ответа.

**Альтернативные потоки:**
- **1.1. Не авторизован.** Если JWT-токен отсутствует или недействителен, система возвращает `401 Unauthorized`.
- **2.1. Некорректные данные.** Если не указан ни текстовый ответ, ни выбранные варианты, система возвращает `400 Bad Request`.
- **3.1. Не владелец попытки.** Если текущий пользователь не является владельцем попытки, система возвращает `403 Forbidden`.
- **3.2. Квиз, попытка или вопрос не найден.** Если квиз, попытка или вопрос с указанными идентификаторами не существует, система возвращает `404 Not Found`.
- **3.3. Попытка завершена.** Если попытка находится в статусе `Completed`, система возвращает `409 Conflict`.
