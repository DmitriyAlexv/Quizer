## Общая архитектура

Проект Quizer построен по принципам **Clean Architecture** (чистой архитектуры) с элементами **DDD** (Domain-Driven Design) и **CQRS** (Command Query Responsibility Segregation). Приложение является **монолитом** — единым развёртываемым приложением, разделённым на слои по проектам.

## Платформы и технологии

### Бэкенд

- **.NET 10** — платформа выполнения.
- **ASP.NET Core Web API** — REST API.
- **EF Core** — ORM.
- **Npgsql / PostgreSQL** — база данных.

- **JWT** — аутентификация.
- **MediatR** — CQRS.
- **FluentValidation** — валидация.
- **Swagger / OpenAPI** — документация API.

### Фронтенд

- **React 19** — UI.
- **TypeScript** — типизация.
- **Vite** — сборка.
- **React Router** — маршрутизация.
- **CSS** — стилизация.

## Структура бэкенда

Бэкенд расположен в каталоге `back/` и состоит из нескольких проектов (решение `Quizer.sln`).

### Проект `Quizer` (Domain + Application)

Ядро приложения. Содержит доменную модель и бизнес-логику (use cases). Не зависит от инфраструктуры.


### Проект `Quizer.Controllers` (Presentation)

Слой представления. Содержит контроллеры, контракты (DTO), валидаторы и фильтры.


### Проект `Quizer.Infrastructure` (Infrastructure)

Слой инфраструктуры. Содержит реализацию доступа к данным, Identity, JWT и миграции.

### Проект `Quizer.Web` (Host / API)

Точка входа приложения. Содержит `Program.cs`, middleware, конфигурацию Swagger и настройки.

### Проект `Quizer.UnitTests` (Tests)

Модульные тесты доменной логики.

## Структура фронтенда

Фронтенд расположен в каталоге `front/` и представляет собой SPA на React.

```
front/
├── index.html
├── package.json
├── tsconfig.json
├── vite.config.ts
└── src/
    ├── main.tsx                      # Точка входа (BrowserRouter, AuthProvider)
    ├── App.tsx                       # Маршрутизация
    ├── index.css                     # Глобальные стили
    ├── api/
    │   ├── client.ts                 # HTTP-клиент (fetch, JWT-заголовки)
    │   ├── auth.ts                   # API-методы аутентификации
    │   └── quizzes.ts                # API-методы квизов
    ├── context/
    │   └── AuthContext.tsx           # Контекст аутентификации
    ├── components/
    │   ├── common/                   # Переиспользуемые UI-компоненты
    │   ├── layout/
    │   │   ├── AppLayout.tsx         # Основной макет
    │   │   └── AuthLayout.tsx        # Макет для страниц аутентификации
    │   └── ProtectedRoute.tsx        # Защищённый маршрут
    └── pages/                        # Страницы
```

### Маршрутизация (App.tsx)

| Путь | Страница | Защищённый маршрут |
|------|----------|--------------------|

## Поток обработки запроса

1. **Клиент** (React SPA) отправляет HTTP-запрос к API.
2. **Контроллер** (`QuizzesController` / `UsersController`) принимает запрос.
3. **ValidationFilter** выполняет валидацию через **FluentValidation**.
4. Контроллер отправляет **команду** или **запрос** через **MediatR**.
5. **Обработчик** (CommandHandler / QueryHandler) выполняет бизнес-логику.
6. Для команд — **доменная модель** изменяет состояние агрегата.
7. **Репозиторий** сохраняет/читает данные через **EF Core**.
8. **UnitOfWork** фиксирует транзакцию.
9. Контроллер формирует **DTO** (контракт) и возвращает HTTP-ответ.

## Обработка ошибок

`ExceptionHandlerMiddleware` перехватывает исключения и преобразует их в HTTP-ответы:

| Исключение | HTTP-код | Описание |
|------------|----------|----------|
| `UnauthorizedException` | `401 Unauthorized` | Не авторизован / неверные учётные данные |
| `ForbiddenException` | `403 Forbidden` | Нет прав (не владелец) |
| `NotFoundException` | `404 Not Found` | Ресурс не найден |
| `ConflictException` | `409 Conflict` | Конфликт состояния (например, квиз опубликован) |
| `ValidationException` | `400 Bad Request` | Ошибка валидации |
| Прочие | `500 Internal Server Error` | Внутренняя ошибка |

## Аутентификация и авторизация

- **JWT Bearer** — токен передаётся в заголовке `Authorization: Bearer <token>`.
- **IdentityService** генерирует JWT-токен при авторизации.
- **ClaimTypes.NameIdentifier** содержит ID пользователя, из которого извлекается текущий пользователь.
- Все эндпоинты, кроме `register` и `authorize`, требуют аутентификации.
- **Авторизация по владельцу** — операции над квизом доступны только его владельцу (`OwnerId`).
